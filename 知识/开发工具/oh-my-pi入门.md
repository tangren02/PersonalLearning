# oh-my-pi 入门

适合 macOS 上第一次使用 OMP，以及在本仓库中核对、整理笔记时随手查阅。仓库内容约定见 [[使用说明]]。

## 1. OMP 是什么与本文版本

**oh-my-pi（OMP）** 是终端里的 AI 编程助手，可以读取项目、修改文件、执行命令并调用工具。本文指 [can1357/oh-my-pi](https://github.com/can1357/oh-my-pi)，官网是 [omp.sh](https://omp.sh)，安装包名是 `@oh-my-pi/pi-coding-agent`，启动命令是 `omp`。它 fork 自 pi，但不要直接套用上游 pi 或其他助手的命令。

**核对日期：2026-10-07；本机版本：`omp/18.8.0`。** 已实测 `omp --version`、`omp --help`，以及 `login`、`models`、`setup` 的子命令帮助；安装、认证、TUI 操作和魔法词没有逐项实测。其余说明来自官方文档与源码，主要固定在提交 [`355b5d9`](https://github.com/can1357/oh-my-pi/commit/355b5d9685529d337875d7d387ef53b1f32e7a72)。该快照包含未发布记录，不能把它的全部行为当作本机 release 的实测结果；发生差异时，先查本机帮助、TUI `/` 补全与 `/hotkeys`。

先分清三种输入位置：

- **系统终端（shell）**：输入 `omp`、`omp login` 等，负责启动和管理。
- **OMP 已打开的输入框（TUI）**：输入 `/model` 等 slash 命令，或直接描述任务。
- **普通任务正文**：可以加入 workflowz 等魔法词；它们不是 shell 命令，也不是 slash 命令。

## 2. 第一次使用：从安装到只读任务

### 先确认是否已安装

在 macOS 的终端输入：

```sh
omp --version
omp --help
```

能显示版本就不必重装。只有尚未安装时，才选择安装渠道；本文以 **已装好 Homebrew** 为前提，使用官方支持的这一条路径：

```sh
brew install can1357/tap/omp
```

没有 Homebrew，可先按 [Homebrew 官网](https://brew.sh/) 安装；其他 OMP 安装方式见文末官方 README，不必同时装多个渠道。

### 完成引导、认证和模型选择

在系统终端运行：

```sh
omp setup
```

无参数时进入首次引导；Python、语音等可选依赖并不是所有新手都要安装。按引导完成需要的配置；如果还没认证，再运行：

```sh
omp login
omp models
```

`omp login` 让你选择模型提供方（provider）并完成对应认证；具体可能是浏览器授权或 API key，取决于渠道。**登录一个 provider 不代表其他 provider 也能使用**；模型目录能列出某模型，也不等于凭据已验证成功。不要把真实密钥写进命令行、笔记或截图。

### 进入可信项目，启动 OMP

在终端切到你信任的项目目录，再启动：

```sh
cd "/你的实际路径/PersonalLearning"
omp
```

上面的路径是语法示例，须替换为本仓库在你电脑上的实际路径，不能原样复制。**先确认项目可信，再启动**：项目可能加载设置、扩展、hooks 等可执行内容，详见第 6 节。

进入 OMP 后，在它的输入框中：

1. 若尚未认证，输入 `/login`；已经完成认证就不必重复。
2. 输入 `/model`，在模型选择界面配置日常使用的 `default` 模型。
3. 发送一项范围明确的只读任务。例如：

> 请先阅读本仓库已有的 AGENTS.md 约定和使用说明.md，再只读解释知识目录的组织方式，列出你实际读取的文件作为依据。不要修改文件、安装依赖或运行测试；不需要读取凭据、用户配置或联网补充知识。若缺少依据，请直接说明。

观察它实际读取了什么、调用了什么工具，而不只看最终回答。需要中断时按 `Esc`。这里的“只读”是任务约束，**不是权限隔离或沙箱**。

## 3. 日常速查：终端、slash 命令与快捷键

### 系统终端命令

以下在 macOS 终端输入，不是在 OMP 对话输入框中输入。

| 命令 | 用途与区别 |
| --- | --- |
| `omp --version` / `omp --help` | 查看本机版本和启动参数；子命令也可用 `omp login --help` 这样的写法查询。 |
| `omp setup` | 首次引导；不是每次启动都要运行。 |
| `omp login` | 交互选择渠道并认证；`omp login <provider>` 可指定渠道。 |
| `omp` | 从当前目录启动交互会话。 |
| `omp models` | 查看模型目录；`omp models <provider>` 按渠道列出，`omp models find <关键字>` 搜索。 |
| `omp --model <provider/model-id>` | 本次启动指定模型；建议完整渠道/模型 ID，避免同名模型混淆。 |
| `omp -c` | 继续最近工作：优先终端关联记录，再找当前项目最近可恢复的会话；不是任意项目的全局最后一条。 |
| `omp -r` | 打开历史会话选择器，自己挑选；`omp --resume <会话ID前缀或路径>` 可直接指定。 |

表中的尖括号内容都是**待替换参数**，实际输入时去掉尖括号。`provider/model-id` 应从你的模型目录选取，不是一个真实模型名称。

### OMP 输入框中的 slash 命令

| 输入 | 用途与区别 |
| --- | --- |
| `/` | 查看本机命令补全；列表可能混有项目或扩展命令，并非全是内置。 |
| `/login` | 在 TUI 中认证；作用与终端的 `omp login` 对应，也可接 provider。 |
| `/model` | 打开模型管理/选择界面，配置保存的模型角色，如 `default`。 |
| `/switch` | 为本会话临时换模型，不改保存的角色分配；也可用 `/switch <provider/model-id>`。 |
| `/settings` | 打开设置；魔法词开关也在这里。 |
| `/hotkeys` | 查看当前实际快捷键绑定。 |
| `/new` | 新建空会话，保留当前模型和设置；适合切换到无关话题，不是恢复旧会话。 |
| `/resume` | 在 TUI 中选择历史会话，也可接会话 ID 前缀；默认当前项目，选择器中可用 Tab 切到全部项目。 |
| `/quit` | 退出 OMP，回到系统终端。 |

`omp --model …` 是启动参数，`/model` 是管理入口，`/switch …` 是当前会话临时切换，三者不要混用。跨项目恢复可能切换工作目录与项目设置，恢复后先确认所在项目。

### 少量够用的快捷键

| 按键 | 常见作用 |
| --- | --- |
| `Enter` | 发送当前输入。 |
| `Shift+Enter` | 换行。 |
| `Tab` | 接受补全；在选择器等界面中可能有其他作用。 |
| `Esc` | 关闭补全或中断当前工作；启用 Vim 模式时可能先切换编辑模式。 |
| `Ctrl+O` | 展开/折叠工具输出，便于检查实际行动。 |
| `Ctrl+R` | 搜索输入历史，不是恢复整个会话。 |

按键可能被终端拦截或被用户重映射，**以 `/hotkeys` 为准**。`Ctrl+C` 有清除草稿、再次退出的交互区别，不要把它当成无条件退出键；需要明确退出时用 `/quit`。

## 4. 在本仓库完整做一项工作，并在下次恢复

以核对 [[知识/C++/面经19-04-指针引用与const|指针、引用与 const 笔记]] 为例：

1. **确定范围**：在本仓库目录启动 OMP，先读已有 `AGENTS.md` 和 [[使用说明]]；指出要处理的笔记，而不是笼统要求“优化全部内容”。
2. **只读核对**：先让它读取笔记及笔记链接的原始文档，列出差异与来源位置，不直接修改。
3. **确认改动**：人工看完报告后，再明确授权需要的修改；原始文档是内容的唯一依据，不用外部知识纠错或补充。
4. **检查交付**：查看实际 diff 与对应验证结果，确认只改了授权范围。此仓库检查原文一致性、覆盖、定位和链接；概念代码不补成完整程序，也不编译验证。
5. **留下接续点**：退出前让它总结已完成事项、涉及文件、已经做过的核对，以及仍需人工确认的地方。

只读核对的输入示例：

> 请核对 知识/C++/面经19-04-指针引用与const.md 与其中链接的原始文档。仅以原始文档为内容依据，检查定义、列举项、结论和来源定位是否一致。先给出差异清单及对应原文位置，不改文件、不制作题卡、不补全概念代码、不做编译验证、不联网纠错。无法读取或辨认的内容请标记待确认，不猜测。

确认报告后，可以明确授权：

> 只修正刚才差异清单中已有明确原文依据的项目，仅修改这份知识笔记，保留原文含义与列举项；疑似原文错误不做外部纠正。完成后列出改动位置、对应原文依据和实际做过的核对，未做的验证请明确说明。

然后自行在编辑器中看 diff，或在系统终端用 `git diff` 查看；已有其他未提交改动时，注意区分本次修改与原有内容。没有修改文件的只读任务，则核对它引用的文件、页码和结论。

**下次继续：**回到同一可信仓库目录，在终端运行 `omp -c`；不确定该续哪一条就用 `omp -r`。已经在 TUI 中则用 `/resume`。恢复后先让它复述上次范围与接续点，并重新读取可能已变化的文件；历史对话不是磁盘当前状态的保证。完全不同的主题用 `/new`，结束用 `/quit`。

## 5. workflowz 与四个内置魔法词

### workflowz 怎么输入

workflowz 是 OMP 官方内置的 **magic keyword（魔法词）**，末尾是字母 z。它要求模型按工作流组织较复杂的任务：先识别范围与接口，再对可独立的子任务分工，收集结果、核对并整合。用户只需在普通提示词正文中输入这个词，不需要编写子代理 API。

适合本仓库的示例（整段作为普通文本输入）：

> workflowz 请只读核对知识/C++目录中各篇笔记与它们链接的原始文档。先列出实际范围，再按可独立核对的笔记分工；只以原始文档为内容依据，汇总不一致、遗漏和来源定位问题。每项附笔记位置及原文位置，无法辨认的内容标记待确认。不要改文件、制作题卡、补全概念代码、编译验证或联网补充纠错。

只有几行文字或单个来源定位要查时，直接提问即可，不必动用多代理。

### 触发条件与边界

- **词必须全小写、作为独立词出现在正文中**，不必放在开头。大写变体不触发；普通句末标点或引号可以紧邻。
- 代码块、行内代码、路径、标识符、函数式写法，以及 XML/HTML 标签或元素内容中的词不触发。实际输入不要给词套反引号。
- 作用于**包含该词的当轮**，不是永久切换工作模式。
- workflowz 要求 `eval` 与 `task` 两个工具都可用，同时 `magicKeywords.enabled` 与 `magicKeywords.workflow` 开启。配置项末尾是 `workflow`，不是带 z 的名称。
- 在 `/settings` → **Interaction** → **Magic Keywords** 检查开关。UI 中的词语高亮可能独立于运行时开关保留，**高亮不证明隐藏指令已注入**。

它的机制是向当轮注入一段内置工作流指令，让模型据此使用工具；不是输入后必定创建固定数量代理的调度器。**不保证并行、提速、省钱、结果正确或每次行为一致**，仍需检查实际工具行动和最终依据。

### 四个内置词对比

下表的词都应作为普通正文中的小写独立词使用，并受总开关与各自开关控制。

| 词 | 主要用途 | 工具或模式条件 |
| --- | --- | --- |
| workflowz | 较具体的分工工作流：界定范围、安排独立任务、收集并整合结果。 | 需要 `eval` + `task`。 |
| orchestrate | 更通用的多代理分工与阶段核对指令。 | 需要 `task`。 |
| jevify | 同质列表的批量判断：先明确问题、标准和筛选方式，再集中检查被标记的项目。 | 需要 `eval`。 |
| ultrathink | 提示模型更谨慎地进行多步推理。 | 无上述工具门槛；**只有 auto thinking 生效时**，才额外把当轮推理强度提高到模型支持的最高档。 |

这些是本次核实的 OMP 功能，不代表上游 pi 默认也具备。能触发指令不等于模型一定正确遵循；小任务不必叠加多个词。

## 6. 常见问题与安全边界

**登录了，为什么仍不能使用模型？** 先核对模型所属 provider 与实际登录渠道是否一致，再用 `/model` 或 `omp models` 检查可选项。目录可见不代表密钥、授权、额度和服务可用性都已确认；分享报错时遮掉凭据。

**命令找不到，或按键没有效果？** 先确认输入位置：`omp …` 在系统终端，`/…` 在 OMP 输入框。TUI 输入 `/` 查本机补全，`/hotkeys` 查实际绑定；他人截图里的命令可能来自项目或扩展。

**workflowz 没有明显效果？** 检查小写独立词、是否误放在代码/路径里、总开关和 `workflow` 开关，以及 `eval`、`task` 是否可用；再看实际工具行动，而不是只看高亮。任务不适合拆分时，没有多代理行动也不必然表示触发失败。

**恢复后不是预期工作？** 用 `omp -r` 或 `/resume` 自己选，确认会话所属项目、当前目录与文件状态。`Ctrl+R` 只是输入历史搜索，不能代替会话恢复。

**安全底线：**

- OMP 能改文件、执行命令；“不要修改”“只读”等提示词不构成权限隔离。不要把未知项目当成安全沙箱直接启动。
- 项目可能加载扩展、hooks、工具、命令、skills、规则或 MCP 等输入；启动前先判断代码来源与项目配置是否可信。关闭某类模型工具也不能据此认定项目代码完全不会执行。
- 不推荐为了省事开启 yolo 或跳过确认的模式。权限确认只是一层控制，不等于完整沙箱。
- 密钥、token、凭据文件内容不要放进命令行参数、提示词、公开笔记、截图或提交记录。导出、dump、分享会话前也应检查隐私，不能默认它们都已脱敏。
- 修改前明确允许的范围；修改后人工检查 **diff 和对应验证结果**。让模型报告“实际做了哪些验证”，而不是把“已完成”视为测试通过。恢复会话或中断任务也不能代替检查已经落盘的改动。

# 作用域与存储期

## 来源与口述主线

Q12「全局变量和局部变量的区别？」在 [[基础面经19_上.pdf#page=12]]。不要把作用域、链接性、存储期混为一谈：作用域决定名字在哪里可见，链接性决定不同声明能否指同一实体，存储期决定存储持续多久；对象生命周期还与构造和销毁有关。

## 三个维度分开回答

命名空间作用域的普通全局变量具有静态存储期，但名字并非在整个程序所有位置自动可见；其他翻译单元通常需要适当声明，且要满足链接规则。例如命名空间作用域 `static int n;` 具有内部链接，不能通过另一个翻译单元中同名 extern 声明就访问它。

普通非 static、非 thread_local 的局部变量通常具有自动存储期，块退出时结束相应存储；但局部 `static` 具有静态存储期，名字仍只在其块作用域可见。局部指针还可能指向动态分配对象，不能由指针名字在块内就推断所指对象的存储期。

“全局在数据段、局部在栈”是常见实现描述，不是 C++ 标准对地址区段的通用承诺。优化可能不把某个变量放进内存，局部 static 也不是普通栈变量。

## 初始化不能只按全局与局部一刀切

静态存储期变量在适用常量初始化或零初始化后，还可能需要动态初始化。普通 `int global;` 会被零初始化；局部 `static int calls;` 也从零开始。普通自动局部 `int x;` 未给出可用初值，C++17 下不能读取这个未初始化 int；`int x{};` 则值初始化为零。类类型局部对象还可能执行构造函数，因此“所有局部变量都未初始化”是错误的。

## 示例片段：局部名字与跨调用状态

以下仅展示变量和函数，省略调用环境。

```cpp
int global_count;            // 静态存储期，零初始化
int visit() {
    static int calls;       // 只初始化一次，跨调用保留
    int per_call{};         // 每次调用都从 0 开始
    return ++calls + per_call;
}
visit();                    // 第一次返回 1
visit();                    // 第二次返回 2
```

`calls` 的名字只在 visit 块中可见，但其值跨调用保留；per_call 每次调用重新初始化。

## 补充与纠错

原题表格的“全局整个程序可见”“局部都在栈”“局部初始化值都未定义”均过度概括。改用上述维度并展示局部 static 与 `int x{}` 反例。存储期与生命周期也不应机械等同：存储已存在不表示非平凡对象已完成构造。

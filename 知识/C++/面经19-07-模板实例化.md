# 模板实例化

## 来源与口述主线

Q19「模板是在什么时候进行实例化？」在 PDF 第 18 页，Q20「为什么模板类一般都是放在一个 h 文件中？」在第 18-19 页。入口：[[基础面经19_上.pdf#page=18]]。本笔记不包含紧接其后的 Q21。

模板描述一族实体，编译器在上下文需要具体特化时按规则实例化。需要隐式实例化的地方一般要能看到相关定义，所以常将模板定义放头文件供各翻译单元包含；这不是“模板语法只能放 .h”。已知有限类型集合时，可在实现文件中提供显式实例化定义。

## 不是见到名字就生成全部代码

仅声明指向某类模板特化的指针，通常不需要该类的完整定义；定义该类型对象或计算 sizeof 等需要完整类型时，会触发相应实例化。类模板实例化也不等于全部成员函数定义立即实例化；未被需要的成员函数体通常不会仅因类对象出现就实例化。

模板定义本身仍会被语法检查，非依赖错误通常不能等到某次实例化才处理；依赖于模板参数的部分则需结合具体参数判断。因此“所有模板错误都等到调用才出现”也是过度概括。

## 示例片段：未使用的成员不急于实例化

只展示模板和用法，省略所在函数。

```cpp
template<class T> struct Box {
    T value;
    int unused() { return value.missing(); }
};
Box<int>* pointer = nullptr; // 仅指针通常不要求完整类定义
Box<int> box{3};             // 需要 Box<int>，不因此实例化所有成员函数体
// box.unused();             // 错误：实例化该函数体时发现 int 没有 missing()
```

## 为什么通常把定义放头文件

每个源文件通常独立翻译。如果头文件只有模板声明，而定义藏在另一个 cpp 文件，使用方不能凭声明自行生成所需函数体；若实现方也没有生成相应特化，最终可能出现未定义符号的链接错误。链接器一般不能凭一个未定义符号替程序推导模板实现。

常见组织方式是把定义直接放头文件，或放进 `.tpp`/`.ipp` 并在头文件末尾包含，关键是实例化所需定义的可见性，不是扩展名。若只支持 int 等有限类型，可在实现文件提供 `template int twice<int>(int);` 这样的显式实例化定义，使用方只看到声明即可链接到该定义。`extern template` 是显式实例化声明，能抑制相应隐式实例化，但不是实现，仍需别处提供定义。新增未提供的类型不自动得到支持。

## 补充与纠错

- Q19 的“遇到具体使用就生成代码”需要细分完整类型需求、成员需求和显式实例化；实例化是语言语义过程，不能把它等同于每次使用都生成一份机器码。
- 原表“链接时确保所有模板实例化的定义都可见”易混淆阶段：隐式实例化所需的模板定义可见性主要是翻译期问题，链接处理已经生成的实体定义与引用。
- Q20 是“一般放头文件”，不是强制；有限类型的显式实例化是有效例外。

# 对象布局与空类

## 来源与口述主线

Q3「struct 与 union」在 PDF 第 4-5 页；Q5「空类能实例化吗」在第 6-7 页；Q6「空类 sizeof」在第 7 页。入口：[[基础面经19_上.pdf#page=4]]、[[基础面经19_上.pdf#page=6]]、[[基础面经19_上.pdf#page=7]]。Q5/Q6 合并学习，避免把同一条非零大小规则背两遍。

先说存储关系，再说生命周期，最后说大小边界：普通 struct 可同时保存各成员；union 的成员共用存储，通常一次只有一个活动成员。两者的 sizeof 都受对齐和填充影响。空类能创建完整对象，完整对象大小非零，通常为 1 字节但不能保证总是 1。

## struct 与 union 的存储和活动成员

对于本题的普通非位域数据成员，struct 为各成员提供存储；union 各非静态数据成员具有相同地址，存储应足够容纳最大成员。union 对齐需满足成员要求，sizeof 可能大于最大成员大小。struct 的成员间及末尾可能有填充，因此不能直接把成员 sizeof 相加当作结构体 sizeof。

union 不会自动记录当前活动成员。`union U { int i; double d; }; U u{3};` 初始活动成员为 i；对这种简单标量成员执行 `u.d = 2.5;` 可以开始 d 的生命周期并结束 i 的生命周期。之后读取 `u.i` 不是可移植的 C++17 类型转换方法。标准存在标准布局结构体的共同初始序列等受限例外，不能因此任意读取不活动成员。

带非平凡构造/析构成员的 union 还需要显式管理相应生命周期，不能把简单标量赋值规则机械套用到所有类型。业务上需要安全的“多种类型之一”，可进一步学习 C++17 `std::variant`；这是补充，不是原题要求。

## 空类、地址和空基类优化

`struct Empty {}; Empty e;` 合法。隐式声明的特殊成员仍使它能被构造/析构。“没有手写成员函数”不代表不能创建对象。完整 Empty 对象的 sizeof 大于零；两个同时存在的、彼此独立的同类型完整对象可被地址区分，数组元素也需要非零步长。

`sizeof(Empty)` 通常是 1，但对齐要求、实现选择等都可能改变结果。尤其不能将一次运行输出当作语言保证。空基类子对象可能通过空基类优化不额外占空间；这与完整 Empty 对象的 sizeof 非零不矛盾。C++20 的 `[[no_unique_address]]` 不属于本笔记 C++17 基线。

## 示例片段：存储复用与大小边界

以下为声明及用法片段，省略所在函数等环境。

```cpp
struct S { char c; int i; };  // sizeof(S) 可能大于两成员大小之和
union U { int i; double d; };
U u{3};                     // i 是活动成员
u.d = 2.5;                  // 现在 d 是活动成员，不再读取 u.i
struct Empty {};
Empty a, b;                 // 独立完整对象可区分；sizeof(Empty) > 0
struct Holder : Empty { int value; }; // 空基类可能不额外占空间
```

口述反例：`char + int` 为什么不一定占 `1 + sizeof(int)` 字节？为满足成员及数组后续对象对齐，可能存在成员间和尾部填充；不把常见的大小数值当作保证。

## 补充与纠错

- Q3 第 4 页表格将 struct 大小写成“所有成员大小之和”、union 写成“最大成员大小”，遗漏填充与对齐。
- Q5 已写“通常 1 字节”，Q6 却写成绝对的 1；统一改成“完整对象大小非零，通常为 1”。
- “每个对象都有唯一地址”不可无限推广到任意子对象；空基类子对象可与其他部分共享地址。应先说清完整对象、子对象及生命周期。
- union 活动成员、共同初始序列和空基类优化是对原题边界的补充。

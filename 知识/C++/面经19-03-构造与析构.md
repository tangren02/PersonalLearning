## 初始化与销毁的一条时间线

对最派生对象，先初始化虚基类（深度优先、从左到右遍历继承图，每个虚基类一次），再按基类声明列表顺序初始化直接非虚基类，再按类内声明顺序初始化非静态数据成员，最后执行构造函数体。无虚继承时，记“基类、成员、函数体”即可。初始化列表的书写顺序不改变这条规则。

正常销毁时，先执行当前类析构函数体，再按构造相反顺序销毁成员、直接非虚基类，最派生对象最后销毁虚基类。执行当前类析构函数体时，它的成员和基类通常仍存活。因此把“先派生后基类”展开时，不可漏掉中间成员。

### 依赖顺序不是编译器替你修复的

若声明为 `int a; int b;`，写 `T() : b(7), a(b) {}` 仍先初始化 a，并读取尚未初始化的 b。C++17 下这个 int 的未初始化读取导致未定义行为；“列表把 b 放前面”不能修复它。应使被依赖成员在类中先声明并先初始化，或让两个成员都从有效参数计算。相反，`T(int x, int y) : b(y), a(x) {}` 虽可能触发重排警告，却不因重排本身而读取未初始化成员。

### 初始化不是函数体内赋值

初始化列表直接构造基类和成员；进入函数体时它们已初始化。对 const 标量成员、引用成员、没有可用默认构造函数的成员，不能指望在函数体内赋值替代所需初始化。类内默认成员初始化器在该成员未被构造函数初始化列表指定时使用；两者都指定时，以初始化列表为准。

### 构造抛异常的边界

补充：若普通非委托构造尚未完成便抛出异常，整个对象的析构函数不会执行，但已经成功构造的基类、成员会逆序销毁；正在构造但未完成的成员，其自身析构函数不会被调用。不要背成“构造函数抛异常就完全不析构”。委托构造中目标构造已经完成后，委托构造函数体再抛异常，存在对象析构规则的差异，不能套用“整个对象永不析构”的绝对句。

## 构造函数分类：不同维度可以重叠

- 默认构造函数可不提供实参调用；不只限于零形参，全部形参有默认实参也可以，例如 `T(int n = 0)`。
- 参数化构造函数是常见教学称呼，不是与其余类别互斥的标准分类。
- 拷贝构造典型为 `T(const T&)`，还允许标准规定的其他 cv 引用形式；若有额外形参，它们必须有默认实参。按值接收 `T(T)` 不是合法的拷贝构造写法。
- 移动构造典型为 `T(T&&)`，也有相应 cv 形式及额外默认形参规则。它可从命名对象经 `std::move` 得到的右值表达式初始化，不只接受临时对象；是否实际移动由重载决议和可用构造函数决定。
- 委托构造在初始化列表中指定本类其他构造函数，如 `T() : T(0) {}`；委托目标是该列表唯一的初始化项，先完成目标再执行委托体。在函数体写 `T(0);` 只是构造另一个临时对象。
- `explicit` 是限制隐式转换的说明符，不是第六种互斥构造机制。`explicit T(int)` 仍可 `T x(1)` 或 `T x{1}`，但不能用该构造做 `T x = 1`；C++17 的复制列表初始化选中 explicit 构造时也不合法。

编译器不会无条件生成所有可用特殊成员。用户声明其他构造函数会阻止无条件获得隐式默认构造函数；用户声明拷贝/移动相关函数或析构函数会影响隐式移动的生成，成员自身不可复制也可能让默认拷贝被删除。需要时用 `= default` 表达意图，但它也不能绕过不可构造的基类或成员。

## 示例片段：初始化顺序与构造分类

只保留声明和关键用法；假设 B、M 的构造析构可用，M 可用 int 构造，省略其实现。

```cpp
struct D : B {
    M first, second;
    D() : second(2), first(1) {} // 仍按 B、first、second、函数体的顺序
    ~D() {}                     // 析构体后：second、first、B
};
```

分类示例不涉及资源所有权：

```cpp
struct Value {
    int x;
    Value() : Value(0) {}        // 默认构造，同时委托构造
    explicit Value(int v) : x(v) {}
    Value(const Value&) = default; // 拷贝
    Value(Value&&) = default;      // 移动
};
Value a{7};                     // 直接初始化可用 explicit 构造
// Value b = 7;                 // 错误：不能隐式使用该 explicit 构造
```

Value 仅持有 int，不宣称移动必定更快或清空来源。上文未初始化读取反例用于解释错误边界，不应执行。

## 补充与纠错

- Q8 的文字说示例初始化列表顺序不同，但原例实际与声明顺序一致；上述 D 片段故意反写，注释标明实际初始化顺序。
- 原文“顺序确保所有依赖关系都能正确处理”容易误解。顺序是固定规则；程序员必须安排正确依赖，语言不会自动修复。
- Q10 把默认构造仅描述为无参、移动仅描述为从临时对象初始化，均不完整；explicit 和委托可与其他分类重叠。
- 第 11 页 MyClass 重复定义 `MyClass(int)`，无法正常编译；原拷贝构造的 `new int[*(other.data)]` 用指向的值当数组长度，并未复制元素，其他构造路径还可能留下未初始化指针。这里不修补传播该资源管理例子，而用无裸指针所有权的 Value 演示分类。
- 虚基类顺序、异常展开、类内默认初始化器和隐式特殊成员条件是针对边界的补充，不冒充原文。

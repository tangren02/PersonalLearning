# 面向对象与继承

## 来源与口述主线

原题 Q1「C++三大特性」位于 PDF 第 1-3 页，Q2「struct 和 class」位于第 3-4 页，Q7「子类不能继承父类的函数」位于第 7-8 页。入口：[[基础面经19_上.pdf#page=1]]、[[基础面经19_上.pdf#page=3]]、[[基础面经19_上.pdf#page=7]]；完整原题目录见 [[基础面经19-原题索引]]。

面试时先说：封装用受控接口维护对象约束；继承表达类之间的关系并复用基类部分；多态让统一接口呈现不同实现。再用一个基类引用调用派生类虚函数的例子落地。最后区分“继承关系”“名称查找”“访问权限”“特殊成员生成”，不要把它们混成一张不能继承的清单。

## 封装、继承、多态

封装不只是把字段标成 private。例如余额必须非负，存取接口应拒绝破坏约束的操作；把所有字段机械地暴露为 setter 仍可能破坏封装。private 是语言访问控制，不是加密或抵抗任意内存访问的安全边界。

public 继承允许在正常可访问、无歧义的场景把派生类当作基类使用。继承也有 protected、private 形式，不局限于 PDF 表格列出的两种。需要复用实现但没有合理替代关系时，不应仅因“少写代码”就声称具有 public 继承语义。

运行时多态的典型形式是：基类声明虚函数，派生类覆盖，通过基类指针或引用调用，选择对象动态类型对应的最终覆盖函数。`override` 让编译器检查确实覆盖了基类虚函数。补充：重载和模板常称为编译期多态，但重载不是虚函数动态分派。把派生对象按值复制到基类会发生切片，所得基类对象不会保留派生部分。

若经基类指针 `delete` 派生对象，基类析构函数应为虚函数；本笔记用自动对象演示调用，避免让手工资源管理干扰核心问题。

## struct 与 class：两项默认值

两者都定义类类型，都能具有成员函数、构造析构、继承、虚函数和访问控制。区别在默认值：struct 的成员及基类继承默认 public，class 默认 private。显式写出访问权限后，不能凭关键词判断封装程度。习惯上 struct 常表示简单数据集合，class 常用于封装行为，但这不是能力限制。

## “继承不到”应拆成四件事

- private 基类成员仍属于基类部分，但派生类通常不能直接访问。基类自己的公开成员函数可以操作自己的 private 成员。友元等访问特例需单独判断。
- C++17 可以用 `using Base::Base;` 继承构造函数。构造派生对象时，其余基类和成员仍按规则初始化；不是复制一段函数体，也不是让基类拷贝构造变成派生类拷贝构造。
- 派生类拥有自己的析构函数、拷贝/移动构造和赋值机制。这些特殊成员处理派生类的整个对象，并调用相应的基类操作；可能被隐式声明，也可能因成员或基类限制而定义为删除。
- 基类 `operator=` 可被派生类隐式声明的赋值运算符隐藏；可用 `using Base::operator=;` 引入合适的基类赋值重载。引入它并不把它变成处理全部派生状态的派生类拷贝赋值。

## 示例片段：动态分派与切片

以下只展示核心声明和用法，省略所在函数等环境。

```cpp
struct Animal {
    virtual int speak() const { return 1; }
    virtual ~Animal() = default;
};
struct Dog : Animal { int speak() const override { return 2; } };
Dog dog;
Animal& ref = dog;
ref.speak();                 // 2：仍是 Dog 对象
Animal sliced = dog;
sliced.speak();              // 1：派生部分已切片
```

继承构造函数可单独看这个片段：

```cpp
struct Base { explicit Base(int) {} };
struct Derived : Base { using Base::Base; int extra = 9; };
Derived d(7);                // 调用适用的 Base 构造，extra 仍初始化为 9
```

## 补充与纠错

- Q2 的“struct 与 C 兼容、class 不兼容”过度概括。C++ struct 可以有虚函数、继承及 C 无法表达的成员类型；互操作要检查具体声明、布局与 ABI，不能由 struct/class 关键词推断。standard-layout 也不是任意跨语言 ABI 的万能保证。
- 第 4 页例子设置 `person01` 后仍调用 `person.display()`，不能演示新对象；若要展示 Bob，应调用 `person01.display()`。
- Q7 的“私有成员不继承”“构造函数不能继承”“赋值运算符一概不能继承”均需按上述规则修正。
- 原 Q1 的多态例子使用手工 new/delete；这里仅保留核心分派，补充切片和虚析构边界。

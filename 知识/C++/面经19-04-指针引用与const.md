# 指针、引用与 const

## 来源与口述主线

Q4 指针和引用的区别在 PDF 第 5-6 页，Q13 常量指针和指针常量在第 13 页，Q18 引用参数在第 16-17 页。入口：[[基础面经19_上.pdf#page=5]]、[[基础面经19_上.pdf#page=13]]、[[基础面经19_上.pdf#page=16]]。

指针是可存储地址或空指针值的对象；引用是绑定到对象或函数的别名机制。普通引用变量定义时必须初始化，绑定后不能重绑，给引用赋值是在修改所指对象。指针可以改指向，引用通常表达必需的借用，但二者都不会自动保证被借用对象仍然存活。

## 指针与引用的几个可检验区别

- `int* p = nullptr;` 是合法空指针；合法引用不能以“空引用”表达无对象。用空指针解引用来造引用不是安全的可选值方案。
- `sizeof(p)` 是指针类型大小，不能武断说总是 4 或 8；`sizeof(r)` 是被引用类型的大小。`&r` 是被引用对象的地址，不是在查询“引用槽位”的地址。实现可以为了实现引用而使用存储，不能因此推断标准要求一个独立可观察的引用对象。
- 指针可构成 `int**`；不能直接声明“引用的引用”，但模板类型推导中的引用折叠是另一套规则，本批不展开。
- 按值传指针，重新给形参指针赋值不改变调用方指针；通过 `*p` 修改对象则可能改变实参对象。需要重设调用方指针时，可用 `T*&` 或 `T**` 等明确接口。

## const 看它限定的是谁

| 声明 | 能改指向吗 | 能通过它改所指 int 吗 |
| --- | --- | --- |
| `const int* p` / `int const* p` | 能 | 不能 |
| `int* const p` | 不能 | 能 |
| `const int* const p` | 不能 | 不能 |

中文“常量指针”叫法容易混乱，面试时优先说“指向 const 的指针”和“指针本身 const”，并写类型。`const int*` 只禁止经该访问路径修改；如果原对象本来是非 const，仍可经其他合法可写路径修改。若原对象本来就是 const，去掉 const 再修改导致未定义行为。

## 引用参数的收益与生命周期边界

`T&` 表达可修改的必需借用；`const T&` 表达只读访问路径，常用于避免复制大对象；若需要可选对象，指针可用 nullptr 表达缺席。小标量按值往往更直接，引用不等于必然更快。引用形参绑定可能涉及临时对象或类型转换，不能把“避免拷贝”扩大为绝对零开销。

引用不会自动追踪对象销毁。返回局部自动对象的引用会悬空；const 也不能修复。直接绑定到某些临时对象的局部 const 引用可延长其生命周期，但绑定到函数引用形参的临时对象通常只活到该调用所在完整表达式结束，不能让函数保存的引用永久有效。

## 示例片段：引用赋值与 const 路径

以下只展示局部用法，省略所在函数。

```cpp
int x = 10, y = 20;
int& r = x;
r = y;                      // x 变成 20，r 仍绑定 x
const int* read = &x;        // 不能经 read 写入 x
int* const fixed = &x;       // fixed 不能改指向
*fixed = 30;                 // x 变成 30，经 read 也能读到 30
read = &y;                  // 合法：read 自身不是 const
// *read = 40;               // 错误：经指向 const 的指针写入
```

## 补充与纠错

- Q4 把引用类比为“总是访问正确房间”的安全通道，忽略悬空引用。绑定不可改变不等于生命周期安全。
- Q13 “指向的数据不能修改”应限定为“不能通过该 const 路径修改”，不能推断原对象绝对不变。
- Q18 大对象用 const 引用常有收益，但不承诺所有类型都更快；原例将 `largeString.length()` 转成 int 传给 `const int&`，存在窄化范围问题，读取长度宜直接使用 size_t，不必为演示引用引入转换。

## Q42：野指针与悬空指针

**野指针**指向随机或不确定的内存地址，通常由未初始化指针造成；指向的内存被释放或重新使用后未及时清零、重新赋值也可能形成这种风险。操作它可能读写不属于程序的区域，导致数据损坏或崩溃。
**悬空指针**指向已经释放的内存；删除对象或内存后未及时把指针设为 nullptr，继续访问可能产生未定义行为、数据损坏或程序异常。
释放内存后将指针设为 nullptr。

### 示例片段

错误访问保留为注释，不应执行；展示未初始化与释放后的两个边界。

```cpp
int* wildPtr;
// *wildPtr; // 未定义行为：未初始化
int* danglingPtr = new int(10);
delete danglingPtr;
// *danglingPtr; // 未定义行为：内存已释放
danglingPtr = nullptr;
```

## Q43：内存对齐的作用

内存对齐是安排数据存储和访问的技术，用于提高内存访问效率。

1. **提高访问速度**：把数据放在处理器预期的地址上，以单个或较少内存访问周期完成读写，减少访问次数。
2. **防止硬件错误**：某些处理器（如 ARM、SPARC）访问未对齐数据可能触发硬件异常。
3. **遵守硬件和编译器约定**：满足 CPU 架构与编译器的对齐要求，优化执行和性能。
4. **平台兼容性**：保证不同平台间数据结构的一致性和正确解析，尤其在网络通信、文件格式中。
5. **提高缓存利用率**：更可能与缓存行边界对齐，减少缓存行加载次数和缓存未命中。

### 示例片段

假设 int 为 4 字节。Aligned 展示自然对齐；Unaligned 用 pack(1) 强制紧凑布局，可能造成性能下降或硬件错误，不作安全访问示例。

```cpp
struct Aligned { int a; int b; int c; };
#pragma pack(push, 1)
struct Unaligned {
    char x; int a;
    char y; int b;
    char z; int c;
};
#pragma pack(pop)
```

## Q62：成员函数中 delete this 的影响

对象内存中只有数据成员和虚函数表指针，没有成员函数代码；成员函数代码放在代码段。
调用成员函数时隐含传递 this，使函数知道由哪个对象调用。
delete this 释放对象内存；只要后续函数调用不涉及 this，仍能正常运行，否则会报错。

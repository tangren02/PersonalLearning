## Q22：new与malloc及减少内存碎片

| 比较项 | new | malloc |
| --- | --- | --- |
| 分配位置 | 堆区 | 堆区 |
| 初始化 | 调用构造函数初始化 | 不调用构造函数，需手动初始化 |
| 返回类型 | 指定类型的指针 | void*，需强制转换类型 |
| 分配失败 | 抛出异常 | 返回 NULL |

减少内存碎片：使用内存池；按需分配大块内存；避免频繁分配和释放；合并相邻空闲块。

### 示例片段

分别分配并释放一个整数；malloc 成功后手动赋值。

```cpp
int* p1 = new int(5);
delete p1;
int* p2 = (int*)malloc(sizeof(int));
if (p2 != nullptr) {
    *p2 = 10;
    free(p2);
}
```

## Q23：分配内存时大小不确定的处理

1. **确定最大可能大小**：预先确定最大可能大小，再用 new 分配。
2. **动态调整大小**：使用 std::vector 或 std::unique_ptr 等，根据需要动态调整内存大小。
3. **类型擦除与多态**：使用基类指针指向派生类对象，动态确定对象的实际类型和大小。

### 示例片段

假设 numElements 是运行时取得的正整数，按该数量分配、使用并释放数组。

```cpp
int* array = new int[numElements];
for (int i = 0; i < numElements; ++i) {
    array[i] = i;
}
delete[] array;
```

## Q24：堆和栈的区别

| 比较项 | 堆 | 栈 |
| --- | --- | --- |
| 内存管理 | 动态分配，由程序员或垃圾回收机制管理 | 函数调用时自动分配，返回时自动释放 |
| 存储内容 | 动态分配的对象和数据 | 局部变量和函数调用的执行环境 |
| 控制方式 | 程序员申请、释放，或垃圾回收机制管理 | 编译器自动控制 |
| 大小和扩展性 | 通常较大，可动态扩展，受操作系统限制 | 大小固定，由操作系统或编程环境预设 |
| 访问速度 | 相对较慢 | 较快，数据通常位于连续内存块 |
| 管理成本 | 较高，可能涉及复杂管理和碎片整理 | 较低，自动分配和回收 |
| 安全性 | 使用不当可能泄漏、产生碎片 | 较安全，但可能栈溢出 |
| 生命周期 | 可在任何时刻创建和销毁，不固定 | 通常随函数执行开始和结束 |
| 使用场景 | 运行时动态分配大量内存 | 函数返回地址、参数和局部变量 |

## Q25：栈溢出的原因

1. **递归调用过深**：每次递归分配包含返回地址、局部变量和参数的新栈帧，层级过深时栈帧累积，耗尽栈空间。
2. **分配过大局部变量**：在栈上分配过大的数组或对象，占用过多栈空间。
3. **无限递归**：没有终止条件，持续分配新栈帧，最终用尽栈空间。
4. **过深的嵌套调用**：调用层级过深，各次调用的新栈帧累积，超出栈容量。
这些情况会造成栈空间用尽，导致程序崩溃。

### 示例片段

这是无限递归错误示例，不应实际调用；没有基准条件，可能耗尽栈空间。

```cpp
void infiniteRecursion() {
    infiniteRecursion();
}
```

## Q25.1：防止栈溢出的措施

1. **限制递归深度**：在递归函数中添加基准条件，限制递归层级。
2. **使用堆分配大数据**：用 new 在堆上分配大数组或大对象。
3. **优化递归**：使用尾递归优化，或将递归改为迭代，减少栈帧使用。
4. **检查嵌套调用**：避免过深的嵌套调用，合理设计函数调用关系。

### 示例片段

假设 n 为非负整数，递归在 n==0 时停止；大数组放在堆上，并在使用后释放。

```cpp
void limitedRecursion(int n) {
    if (n == 0) return;
    limitedRecursion(n - 1);
}
int* arr = new int[1000000];
arr[0] = 1;
delete[] arr;
```

## Q26：内存泄漏检测工具

1. **Valgrind**：内存分析工具，检测内存泄漏和无效内存访问。
2. **AddressSanitizer**：编译器支持的内存错误检测工具。
3. **LeakSanitizer**：专门检测内存泄漏。
4. **Visual Studio**：提供内置的内存分析和检测工具。

## Q27：RAII思想与资源释放

RAII 是 Resource Acquisition Is Initialization，即“资源获取即初始化”。

1. 对象创建时获取资源。
2. 对象析构时自动释放资源。
3. 通过对象的作用范围控制资源生命周期。
4. 异常发生时也保证资源正确释放，提供异常安全性。
将资源与对象生命周期绑定，能够自动管理资源，避免资源泄漏和未定义行为。

### 示例片段

摘取文件资源的获取与释放；假设 file 是 FileRAII 的 std::fstream 成员，filename 类型为 const std::string&，省略写入方法和其余类体。

```cpp
FileRAII(const std::string& filename) {
    file.open(filename, std::ios::out | std::ios::trunc);
    if (!file.is_open()) throw std::runtime_error("Unable to open file");
}
~FileRAII() {
    if (file.is_open()) file.close();
}
```

构造时打开文件，打开失败抛出异常；对象析构时关闭已打开的文件。

## Q21：define宏定义与const及static的区别

| 比较项 | define 宏定义 | const | static |
| --- | --- | --- | --- |
| 类型检查 | 不进行类型检查 | 进行类型检查 | 进行类型检查 |
| 作用范围 | 全局 | 作用域内有效 | 作用域内有效 |
| 存储方式 | 编译时替换文本 | 编译时常量 | 静态存储，生命周期贯穿整个程序 |
| 调试支持 | 调试困难，无法设置断点 | 可以设置断点 | 可以设置断点 |
| 用途 | 简单常量或复杂表达式 | 常量或只读数据 | 静态变量或静态成员变量 |

define 通过预处理器进行文本替换，缺乏类型检查；const 定义常量，类型检查提高安全性；static 定义静态变量或成员，具有文件内或函数内的局部作用域，在程序生命周期内保持值的持久性。

### 示例片段

保留常量声明和静态计数；每次调用 incrementCounter，localCounter 与 counter 都递增并保留其值。

```cpp
#define PI 3.14159
const int MAX_SIZE = 100;
static int counter = 0;
void incrementCounter() {
    static int localCounter = 0;
    ++localCounter;
    ++counter;
}
```

## Q49：内联函数与宏定义的区别

| 比较项 | 内联函数 | 宏定义 |
| --- | --- | --- |
| 类型检查 | 进行类型检查 | 不进行类型检查 |
| 调试 | 支持调试和断点 | 调试困难，无法设置断点 |
| 安全性 | 有类型安全性和作用域范围 | 缺乏类型安全性和作用域范围 |
| 代码替换 | 编译器在调用处内联展开 | 预处理器进行文本替换 |

两者在性能优化上有相似之处；内联函数更安全、更灵活，适合短小函数；宏缺乏类型检查，容易产生难以发现的错误。

### 示例片段

平方宏与内联函数的比较。

```cpp
#define SQUARE(x) ((x) * (x))
inline int square(int x) { return x * x; }
int a = 5;
SQUARE(a + 1); // 输出 11，错误结果，注意括号
square(a + 1); // 输出 36，正确结果
```

## Q50：内联函数的使用建议

适合使用的场合：函数短小；调用频繁；需要类型安全检查；需要调试和断点。
应尽量保持函数简短，便于编译器展开和优化。
inline 只是建议，最终是否内联由编译器决定。编译器考虑复杂度、大小、调用频率和优化设置；复杂或过大的函数可能不内联，高频调用的短小函数更可能内联。

## Q60：局部static初始化的线程安全

1. **初始化时机**：全局 static 在程序启动时初始化，局部 static 第一次使用时初始化；编译器与运行时控制初始化只进行一次。
2. **固定内存位置**：static 存在于全局/静态存储区，贯穿程序生命周期，多个线程访问同一内存位置。
3. **单次实例化**：类似单例模式，由编译器和运行时保证只实例化一次，避免初始化竞争。
4. **多线程机制**：C++11 规定，局部静态变量由第一个进入作用域的线程完成初始化；其他线程阻塞等待，直到初始化完成。编译器在初始化代码周围插入同步机制。

**常见实现方式**：初始化代码周围加互斥锁；某些平台使用原子操作；双重检查锁定先检查是否初始化，未初始化再加锁，以减少不必要的锁开销。
**注意范围**：全局静态变量、命名空间静态变量、类的静态成员变量没有内置的线程安全保证。

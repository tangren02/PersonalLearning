# 智能指针与并发

## 来源与口述主线

Q14 智能指针缺点在 PDF 第 13-14 页；Q15 shared_ptr 线程安全在第 14 页；Q16 智能与裸指针选择在第 14-15 页；Q17 shared_ptr/weak_ptr 在第 15-16 页。入口：[[基础面经19_上.pdf#page=13]]、[[基础面经19_上.pdf#page=14]]、[[基础面经19_上.pdf#page=15]]。

先讲所有权，再讲成本和并发：unique_ptr 表达独占，shared_ptr 表达共享，weak_ptr 是不延长对象生命周期的观察，裸指针或引用常表达借用。shared_ptr 的共享控制机制保护所有权管理，不自动保护所指对象的数据。

## 选择与成本

需要独占资源时通常用 unique_ptr，不需要共享就不应为方便复制而默认使用 shared_ptr。需要多个独立拥有者共同决定释放时使用 shared_ptr；需要观察共享对象又不保活时使用 weak_ptr。仅在调用期间借用对象，可以用裸指针或引用并明确生命周期；不要把裸指针从语法上等同于不拥有，遗留 API 仍可能要求调用者释放资源。

shared_ptr 通常涉及控制块、引用计数及其同步成本，循环强引用会导致对象不释放。unique_ptr 不使用共享引用计数，其大小和成本受删除器等影响，不能把 shared_ptr 的全部缺点套到所有智能指针。自动释放也不等于逻辑无误，错误所有权图、重复建立独立控制块等仍有风险。是否存在性能瓶颈应实际测量。

## strong 与 weak：打断拥有关系，不是把赋值表达式改个名字

最后一个共享拥有者释放时，对象按删除器规则销毁；weak_ptr 不增加强引用计数，不能直接解引用。weak_ptr 仍参与弱观察管理，控制块可能比所指对象存活更久，所以“不增加引用计数”应精确成“不增加强引用计数”。

假如 A 强持有 B，B 又强持有 A，即使外部拥有者全部释放，环内强引用仍使计数不能归零。将不应拥有对象的一条回边改为 weak_ptr，再通过 `if (auto p = weak.lock())` 临时获取强引用。lock 原子地尝试获得强拥有权：成功返回 shared_ptr，过期返回空。先检查 expired 再假设对象仍活着存在竞态窗口；即便 lock 成功，也只保证拥有权，不替对象字段加锁。

## 三层线程安全

1. 不同 shared_ptr 实例共享同一控制块：线程可各自复制、销毁或 reset 自己的实例，控制块会安全地管理共享计数。
2. 同一个 shared_ptr 变量：若并发操作中含 reset/赋值等修改，普通读写需要同步；C++17 可用互斥锁，或配套的 `std::atomic_load`/`std::atomic_store` shared_ptr 自由函数。使用原子路径时不能混入不受同步保护的普通访问。
3. 所指对象：并发写普通字段仍需对象自己的锁、原子成员或其他同步策略；只读且没有并发写入等情况另论。

`std::atomic<std::shared_ptr<T>>` 特化从 C++20 才提供，不属于本批 C++17 写法。原 PDF 多线程示例复制 shared_ptr 并只读 int，不能证明“同一指针变量任意写”和“对象字段并发写”安全。

## 示例片段：真正的弱回边

省略头文件和所在函数，只展示拥有关系：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> previous; // 回边的类型本身就是 weak_ptr
};
auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->previous = a;                  // 不增加 a 的强引用计数
if (auto owner = b->previous.lock()) {
    // owner 在此作用域内保活 a；不代表对象字段可随意并发写
}
```

这里不再构造完整线程测试程序；对象字段的同步与指针拥有权是两个问题，按上面的三层规则判断。

## 补充与纠错

- Q14 的成本必须按智能指针种类区分；unique_ptr 没有 shared_ptr 的共享引用计数成本。
- Q15 需补上“同一个 shared_ptr 变量”层，不能只区分计数与对象。
- Q16 以所有权为先，不应因“性能要求高”就直接手工 new/delete；裸指针借用也要保证存活。
- Q17 原例把 weak_ptr 赋给仍声明为 shared_ptr 的 next，不能编译，且没有真正建立弱回边。本例把回边的成员类型声明成 weak_ptr，并用 lock 使用它。

## Q14：智能指针的缺点

主要有三项：性能开销；循环引用导致内存泄漏；代码复杂性增加。

建议防止循环引用、了解性能影响，并在必要时优化。示例中两个 Node 的 shared_ptr 成员 next 相互指向，形成循环引用。

## Q15：shared_ptr 是否线程安全

引用计数操作是线程安全的，所管理的对象本身不是线程安全的；对象的读写需要额外同步。

使用场景：适用于多线程共享同一对象。

示例由 shared_ptr<int> 管理值为 100 的整数，将 shared_ptr 传值给 10 个线程，每个线程打印该值，最后逐个 join。

## Q16：智能指针与裸指针的使用场景

智能指针：

1. 自动管理资源生命周期。
2. 防止内存泄漏。
3. 管理复杂的所有权和生命周期。
4. 异常发生时正确释放资源。

裸指针：

1. 简单临时对象，不涉及所有权。
2. 性能开销要求高。
3. 不需要管理生命周期。

图示将这些场景概括为“自动资源管理、防止内存泄漏、复杂对象管理、异常安全性”和“简单临时对象、性能要求高、不涉及所有权”。

## Q17：shared_ptr 与 weak_ptr

| 比较项 | shared_ptr | weak_ptr |
| --- | --- | --- |
| 所有权 | 共享拥有对象 | 不拥有对象 |
| 引用计数 | 增加引用计数 | 不增加引用计数 |
| 生命周期 | 控制对象生命周期 | 不控制对象生命周期 |
| 循环引用 | 可能导致循环引用 | 可用于打破循环引用 |

## 示例片段：循环引用

摘取 Q14、Q17 中相互持有的关系，省略外围函数和输出。这是可能导致内存泄漏的循环引用示例。

```cpp
struct Node { std::shared_ptr<Node> next; };
auto node1 = std::make_shared<Node>();
auto node2 = std::make_shared<Node>();
node1->next = node2;
node2->next = node1;
```

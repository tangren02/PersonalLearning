# 拷贝与移动语义

AI 原创学习草稿，需用户核对；仅用于个人学习，不含工作资料。

## 面试要点

- 拷贝按类型定义复制状态；深拷贝不是语言对每个类型的自动保证。移动允许从将不再需要原值的对象中转移资源，也可能只是复制少量标量。
- `std::move(x)` 只把表达式转换为适合移动重载参与选择的值类别，本身不搬资源。实际调用哪个函数由重载决议决定。
- 对 `const T` 使用 `std::move` 得到 `const T&&`；通常不能绑定接受 `T&&` 的移动构造函数，可能转而调用 `const T&` 拷贝构造。
- 优先采用“零法则”：让标准容器、智能指针成员管理资源。自己管理裸资源时，要整体检查析构、拷贝和移动操作；用户声明析构函数会阻止隐式移动操作的生成。

## 小例子与边界

```cpp
#include <string>
#include <utility>

void example() {
    const std::string source = "hello";
    std::string target = std::move(source); // 通常的 string 拷贝构造
}
```

标准库对象被移动后通常处于有效但值未指定的状态，除非具体接口有更强规定；不能泛化成“一定为空”。用户自定义类型的移动后状态由其契约决定。为移动操作正确标注 `noexcept` 有助于容器在满足异常保证的条件下选择移动；不要承诺实际上做不到的不抛异常。

## 标准版本

C++11 引入右值引用和移动语义。C++14 延续这些基本规则。C++17 中 `T x = T{};` 等同类型纯右值初始化直接构造目标，不需要可用的拷贝/移动构造函数（析构函数仍有可访问、未删除等要求）；`return local;` 的 NRVO 仍非强制，`return std::move(local);` 还会妨碍 NRVO。

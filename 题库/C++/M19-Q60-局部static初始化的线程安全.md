为什么局部 static 变量的初始化是线程安全的？说明初始化时机、固定存储、单次实例化、多线程等待机制和常见实现方式，并列出不具备内置线程安全保证的静态变量类别。
?
1. **初始化时机**：全局 static 在程序启动时初始化，局部 static 第一次使用时初始化；编译器与运行时控制初始化只进行一次。
2. **固定内存位置**：static 存在于全局/静态存储区，贯穿程序生命周期，多个线程访问同一内存位置。
3. **单次实例化**：类似单例模式，由编译器和运行时保证只实例化一次，避免初始化竞争。
4. **多线程机制**：C++11 规定，局部静态变量由第一个进入作用域的线程完成初始化；其他线程阻塞等待，直到初始化完成。编译器在初始化代码周围插入同步机制。
**常见实现方式**：初始化代码周围加互斥锁；某些平台使用原子操作；双重检查锁定先检查是否初始化，未初始化再加锁，以减少不必要的锁开销。
**注意范围**：全局静态变量、命名空间静态变量、类的静态成员变量没有内置的线程安全保证。
